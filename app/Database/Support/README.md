11:00–12:00 were recovered from `62c7a2b7^`. Commit `62c7a2b7`
removed them together with the former accounting services and screens.

preserved. Only dependency references now point to `LegacyAccounting202609`.

the historical `LrReportRows`, `OracleLrSalaryParser`, and

- `LrReportRows::branchFormulaSourceMappings()` (11 rows)

The helper also preserves the historical label normalization and the three
source-adjustment table constants. Do not replace this snapshot with current
report mappings: historical migrations must remain reproducible.

## Isolated integration verification

`tests/rka/legacy_accounting_migrations.php` accepts a backup directory and a
NEW database prefix `jaksa_migration_test_YYYYMMDD_HHMMSS`. It requires the
local source database to be `operasional`, checks the backup SHA-256, refuses
existing target databases, restores the backup into a new `_restore` database,
and directs the application default connection to that copy before booting.
Source fingerprints are read-only and include every table's data and DDL.

It verifies backup round-trip equality, migration-runner no-op behavior on
the restored database, eight migrations up/down/up on `_fresh`, all five
legacy table schemas against the source, representative mapping values,
deterministic rebuilt mapping data, and unchanged source fingerprints.
It retains both test databases and writes `verification.json` next to the backup.

This is not certification of a full application installation from empty:
the four pre-repository migrations and the users ID type discrepancy remain
outside this recovery. Do not delete migration history or run rollback on
`operasional` to address those separate issues.
